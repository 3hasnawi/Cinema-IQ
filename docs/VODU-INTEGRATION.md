# ربط VODU في سورس CinemaIQ 3.1

أضيف مصدر VODU مباشرة عبر HTTPS باستخدام OkHttp وJsoup، بدون خادم Python أو إعداد عنوان API. تستخدم الرئيسية وصفحات الأفلام والمسلسلات والبحث صفوف VODU ضمن عناصر العرض الحالية. تعرض الأفلام والمسلسلات الإنجليزية (تصنيفا الموقع 0 و1)؛ بقية تصنيفات VODU ليست مضافة في هذا الإصدار.

عند تعذّر مصدر تستمر نتائج المصدر الآخر وتظهر رسالة تفيد بوجود فشل جزئي. العرض التجريبي يحتفظ بسلوكه الحالي. تسجيل الدخول الموجود يخص Cinemana؛ قراءة VODU لا تستخدم رمزه.

توجّه CinemanaApi الأعمال التي تبدأ معرّفاتها بـ`vodu:` إلى VoduApi. الأفلام والمسلسلات تستخدم `vodu:<title-id>` والحلقات `vodu:<parent-title-id>:<episode-id>`؛ بذلك يمكن استرجاع الحلقة من صفحة مسلسلها بعد حفظها في المفضلة أو السجل. الحفظ والتقدم الحاليان يقبلان هذه المعرّفات دون تغيير تنسيق المكتبة.

تُقرأ بيانات السنة والتقييم والمدة والقصة والبوستر والتريلر من HTML. تُقرأ المواسم والحلقات وروابط MP4 المتاحة من سمات data-*، وتُرسل الجودات إلى المشغل الحالي. تُستخدم WebVTT العربية للتوافق مع MIME الحالي للترجمات. لم تُضف SRT منفصلة عندما تتوفر WebVTT لنفس الترجمة. تسمية data-url بـ720p تتبع إعداد مشغل الموقع، ولم يتم فحص دقة الملف نفسه.

تُخزن الصفحات لمدة خمس دقائق داخل الذاكرة وبحد أقصى 64 صفحة. يعتمد المصدر على بنية الموقع؛ تغيير HTML أو قيود الوصول قد يحتاج تحديث الموصل. لم يتم تنزيل أو تضمين ملفات فيديو داخل المشروع.

اختبارات VoduParserTest تغطي تفاصيل فيلم The Wild Robot والجودات والترجمة، مسلسل Shogun ذي عشر حلقات ومعرّفاتها، معرّفات الكتالوج والحفظ، الصفحات غير الصالحة والروابط الفارغة. عينات HTML موجودة ضمن test/resources/vodu؛ الاختبارات لا تطلب الشبكة.

التحقق بتاريخ 6 أكتوبر 2026: نجح تجميع كود التطبيق واختبارات الوحدة الـ29 (25 سابقة و4 خاصة بـVODU)، دون إخفاق أو اختبار متروك. جرى تشغيل `:app:testDebugUnitTest` باستخدام JDK 17 وAndroid SDK 36 وGradle 8.13، مع خيار `-Pkotlin.compiler.execution.strategy=in-process` لتجاوز مشكلة خدمة Kotlin الخلفية في الجهاز المحلي. لم يجر اختبار تشغيل الفيديو داخل التطبيق على تلفزيون فعلي.

بعد طلب المستخدم «وقعه وصدره» وتأكيده «وقعه جديد»، أُعد إصدار Release جديد باسم 3.2 ورقم versionCode=34، مع بقاء الحزمة com.cinemaplus.rebuilt. يستخدم مفتاحاً جديداً خاصاً بـCinemaIQ؛ لذلك لا يستطيع تحديث APK القديم ذي توقيع Android Debug السابق مباشرة. يجب استخدام المفتاح الجديد نفسه للإصدارات القادمة. المفتاح وكلمة مروره خارج سورس المشروع وفي حزمة احتياطية منفصلة.

نجح بناء Release وفحص lintVital واختبارات Release الـ29. جرى التحقق من توقيع APK بصيغتي v2 وv3، ومحاذاة zipalign بحجم صفحة 16KB، ورقم الإصدار 34/3.2، وعدم تفعيل debuggable. لم يجر اختبار التثبيت أو التشغيل على جهاز فعلي.

## تعديل ظهور المحتوى تدريجياً

في السورس المعدّل بعد إصدار APK 3.2، تُنشر صفوف كل مصدر فور وصولها، قبل انتهاء بقية المصادر. عند وصول صفحة إضافية تُدمج العناوين دون تكرارها أو حذف الصفوف المتاحة. تبقى أخطاء المصادر معزولة، وإلغاء الطلب عند تغيير الصفحة أو البحث يمنع نشر نتائج الطلب الملغى. يبقى ترتيب الصفوف النهائي كما كان. لا توجد تغييرات في التصميم.

تغطي ProgressiveSourcesTest وصول VODU بينما Cinemana ما زال ينتظر، واستمرار النتائج عند فشل مصدر، وعدم نشر نتائج الطلب الملغى. هذا التعديل لم يُصدّر في APK جديد بعد.

## اختيار المصدر

الإعدادات ← المحتوى ← مصدر المحتوى. الضغط على الصف يتنقل بين «سينمانا وVODU» و«سينمانا» و«VODU». يُحفظ الاختيار على الجهاز ويُستخدم في الرئيسية والأفلام والمسلسلات والبحث. عند اختيار مصدر واحد لا تُرسل طلبات قوائم للمصدر الآخر. المفضلة والسجل يبقيان محفوظين، وتظل الأعمال المحفوظة قابلة للفتح باستخدام مصدرها الأصلي. اختيار المصدر لا يعطل العرض التجريبي تلقائياً؛ عطّله لعرض المحتوى الحقيقي. هذه الإضافة في السورس، ولم يُصدّر APK لها بعد.
