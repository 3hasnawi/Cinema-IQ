# IPTV source keyboard and focus correction

The user reported a keyboard/focus hang when adding a source in Android 4.37. Input traversal and keyboard dismissal take priority for all future field changes; the instruction is persisted in AGENTS.md and docs/COLLABORATION.md.

Reserved scope: IptvTvForms.kt, a dedicated TV field editor and source-form traversal policy/tests, source-dialog input validation tooling, and the existing Android TV validation workflow. No player redesign, package/version change or public publication. Existing credential storage stays unchanged.

Original implementation findings: source fields relied on implicit spatial focus and default IME actions. The dialog requested initial focus outside its own window, with no explicit keyboard dismissal on submit/cancel or route through Xtream's conditional fields. The baseline emulator reproduction below confirms the navigation/Enter symptoms.

The baseline reused an existing approved signed APK without rebuilding it. The user then explicitly authorized the repaired test APK and its real remote/keyboard validation. The latest expanded results and remaining limits are recorded in PR #141; compile/unit checks are separate from runtime evidence.

Implemented repair: TV fields are explicitly navigable controls; OK opens a single-field editor. IME Next/Done commits the draft, hides the keyboard and restores the next form target. Back hides the IME before leaving the editor; cancel returns to the original field. A source-type-aware focus graph excludes hidden fields/disabled Connect, supports arrows and Tab, and leaves Cancel reachable during connection. The dialog requests initial focus inside its own focused window, one time only, applies IME insets, and releases its input session on disposal. Phone fields retain their inline design with explicit Next/Done handlers.

Baseline run 44059034377 reused the signed 4.37 APK from run 44053028135. Genuine emulator capture 02-name-navigation.png shows the keyboard opening on D-pad traversal to the name; 04-enter-next.json records the name still focused after Enter, rather than the address. The old input-method `mInputShown` flag remained stale after the keyboard was visually gone, so keyboard-visibility detection now inspects the actual WindowManager IME window; that baseline's Back-only assertion is not treated as reliable evidence. Initial dialog focus and leaving the form passed. Earlier attempts failed in the harness before this reproduction and are not app-test results.

The user authorized the fixed test APK. Build run 44063477250 produced one Debug APK from 71d3722. A replay on that exact APK (run 44065281676) passed all 14 real Android TV D-pad/IME checks: browse without opening the keyboard, explicit edit, Enter-to-address, switching to Xtream with physical Left/OK, every Xtream field, password-keyboard Back, and restoring the password control. APK SHA-256: 1595511caaf58207fc79dadb674d2978e5701d0ca7f29d373d7dcb2db7cd918f. This was the first repair APK. The expanded run 44068712862 confirmed native M3U Done commits its URL but exposed a lost first Down event after returning to the form; it was not a full regression pass.

The first fixed test exposed stale input-service visibility flags and touch-based source-mode selection in the harness; genuine captures already showed correct address focus and a hidden keyboard. Detection now reads the actual WindowManager IME window and source selection uses real remote events. Replays reuse the approved APK without rebuilding it. The expanded regression additionally fills M3U/Xtream URLs, username/password, invokes the native keyboard's Done/Next action with D-pad events, checks password masking, and navigates Connect/Cancel. Its latest results are recorded in the PR.

The source_input and reuse_input_run_id workflow paths remain manual. Only emulator input coverage is claimed: no real TV, live-provider connection or production release has been tested/published in this task.

The follow-up repair keeps field editing and source browsing in one persistent dialog window, restores form focus after the IME is actually hidden, and waits for the activity window to regain focus before restoring its source toolbar. This removes cross-window focus handoffs between consecutive inputs. The current APK must be rebuilt and the complete native regression rerun; PR #141 records the final APK provenance and results.
